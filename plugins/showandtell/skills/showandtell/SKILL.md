# Showandtell

Enabled hooks record supported unified computer-use calls and automatically queue a local video after the turn. Default `actions` mode takes a screenshot after each supported action returns and a baseline before a surface's first action when the current turn has no image of that surface. Follow the computer-use tool's first-call and observation rules; do not manually bootstrap capture when hooks work. Start a new chat after upgrading.

- Use public `cua` app/tab methods. Keep a named mutable `let`/`var` handle from `cua.getApp`, `cua.getTab`, or `cua.createBrowserTab`. Required first discovery stays unchanged; the next call installs recording and wraps the handle. Reacquire into a mutable binding if an immutable handle cannot be instrumented.
- All modes also save bytes from normal `getScreenshot` and optional `getAXStateAndScreenshot.screenshot` results, preserving their normal results without duplicate image emissions. Default action capture preserves intermediate results even when several actions share a tool call. Its extra screenshot calls and local writes are awaited; background app operation does not make capture asynchronous or zero-cost. Follow normal tool observation rules without adding redundant screenshots solely for recording.
- Coordinate actions supply cursor targets when a preceding screenshot of that surface exists. Accessibility-index actions expose no coordinates, so their synthetic pointer is hidden. For an explicitly requested cursor demonstration, use fresh screenshot observations and coordinate actions. Snapshots show the screen after an action returns; press-down states, animations, per-character typing, and scroll transitions between screenshots are not live footage. Motion is reconstructed.
- Stop collects remaining files and launches a short-lived detached export process. The answer does not wait for rendering. Check `status`, `video.mp4`, and `export.json` before claiming completion; do not start duplicate exports. Captures live under `~/.showandtell/<session>/<turn>/` or `claude-<session>/<turn>/`. An error or machine shutdown can be retried from saved capture. Never upload without the user's request.
- Local launcher: `sh <plugin-root>/scripts/run.sh status [capture-directory]`, `doctor`, or `export <capture-directory>`. In a Codex package, resolve `<plugin-root>` two levels above this skill's directory. For the installed Claude skill at `~/.claude/skills/showandtell`, use `~/.showandtell/runtime` instead. `SHOWANDTELL_HOME` may override capture storage.
- Claude support targets exactly `mcp__codex-cu__js` and uses normal Claude permissions. Its optional setup reuses the bundled local Mac MCP; the backend needs a running desktop and app consent. The headless native test stopped at app approval; external browser calls required missing Codex turn metadata. Report these blockers without auto-approving consent or forging host metadata. Do not claim universal headless compatibility or a standalone public API. `SessionEnd` also recovers saved turns.
- Optional `SHOWANDTELL_CAPTURE=reuse` in the environment launching the agent requests no extra screenshots and can miss states between observations. Accessibility text and inaccessible internal/first-discovery images are not frames, so reuse mode may produce no video. `SHOWANDTELL_CAPTURE=full` adds a screenshot before and after every supported action. `actions` is the default. Do not silently change modes. `SHOWANDTELL_DISABLED=1` disables hooks. To stop persistent capture, disable the Codex plugin/hooks or remove Showandtell's Claude hook entries.
- Storage warnings mean capture is incomplete. Report `capture-storage-unavailable` or `capture-storage-write-failed`; inspect local file access without weakening permissions or relying on truncated transcript images.
- If Codex hooks are not trusted, direct the user to review Showandtell in `/hooks`; do not change trust settings. Check saved frames before claiming automatic recording worked. Legacy import cannot recover omitted screenshots or exact pointer paths.

Exports stay local. Marker metadata omits typed text, keys, URLs, and raw tool code; screenshots may contain visible private information.
